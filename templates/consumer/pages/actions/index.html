How this page works

dispatch · live

A thin front-end over the GitHub REST API: it reads this repository with your own access and dispatches the Code Build workflow. No backend — everything runs in your browser, so you only ever see what GitHub already lets you see.

1 · read
Reads the repo's branches, then the chosen branch's build/build-config.yml, with your token.
2 · cascade
The config becomes branch → module → service; each dropdown filters the next.
3 · dispatch
workflow_dispatch on the default branch with your service + build branch. Needs Actions: write.
4 · watch
The DIGIT-DevOps engine builds, scans and pushes; Recent runs polls the status live.

Your token stays in this browser tab only (session storage): it survives a refresh, clears when the tab closes or after 15 min idle, and a strict Content-Security-Policy means it is only ever sent to api.github.com — nothing here can send it elsewhere.

Trivy security gate

gh-pages · /security/trivy

pattern · DIGIT-DevOps reusable CI

Every build is scanned by Trivy. A CRITICAL finding blocks the pipeline; the report is published either way, so history is never lost.

  1. Code scan — the source tree is scanned for vulnerable dependencies & secrets, before the image is built.
  2. Build — the service image (and its DB image, if any) is built.
  3. Image scan — the built image is scanned for OS + library CVEs, before it is pushed.
  4. Gate — a CRITICAL at either scan aborts the run; HIGH and below are reported.
  5. Publish — results land on gh-pages/security/trivy.
