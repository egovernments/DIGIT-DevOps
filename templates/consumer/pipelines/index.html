Trivy security gate

gh-pages · /security/trivy

pattern · health-campaign-services

Every Code Build runs aquasecurity/trivy-action against the source tree and the built image. A CRITICAL finding blocks the gate; the report is published to gh-pages regardless, so history is never lost.

  1. Code scan — filesystem scan of the service work-dir.
  2. Image scan — the pushed image is scanned for OS + library CVEs.
  3. Gate — CRITICAL aborts the build; HIGH and below are reported.
  4. Publish — results land on gh-pages/security/trivy.

› How this page works
1 · read
The browser calls the GitHub REST API with your token for branches, then that branch's build-config.yml.
2 · cascade
Config is parsed into module → service → image-name. Each dropdown filters the next.
3 · dispatch
Run posts to the workflow_dispatch API with ref + service. Needs Actions: write.
4 · watch
The run executes the DIGIT-DevOps engine + Trivy; this page polls its status and links to it.

The token lives only in this tab's memory. It is never stored, and a strict Content-Security-Policy means it can only ever reach api.github.com — nothing on this page can send it elsewhere.
